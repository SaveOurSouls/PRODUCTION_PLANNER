# Рабочий контекст — Поток / Production Planner

Обновлено: 23.09.2026. Репозиторий: https://github.com/SaveOurSouls/PRODUCTION_PLANNER

## Цель и текущая точка

Создать рабочее место одного производственного планировщика: маршрут изготовления → нормы → назначения людей/оборудования → факт и брак → движение полуфабрикатов. Пользователь утвердил два результата: самостоятельное HTML-демо и серверную v1 на Next.js, TypeScript, PostgreSQL, Prisma и React Flow.

Код обоих результатов создан. Готовое демо находится в `demo/production-planner.html`. Сервер, отдельный worker и база описаны в `docker-compose.yml`. Внешнее развёртывание ещё не подтверждено. Базовая реализация опубликована в `origin/main`, коммит `20b7a4f`. Сохранена история исходного GitHub-коммита `ce5d245`. Текущие правки интерфейса по С1–С3, общей таблице остатков и вытягивающему режиму находятся в ветке `codex/semifinished-planning-views`; обычный `git pull` из main их не подхватит.

## Последнее изменение — интерфейс по С1–С3

Реализовано 23.09.2026:

- В нормативной таблице одна строка на полуфабрикат: название и индекс, сумма времени последовательных операций, подготовка, потребность и трудозатраты. Ошибочная/пустая норма отображается как неизвестная. Срок завершения берётся из расписания.
- В блоке схемы компактная строка «номер операции / время», редактирование поправки, возврат к расчёту; подробные параметры и порядок операций вынесены в отдельное окно. Ниже машинного предела цикл не опускается.
- «БД.ОП» в навигации: штатная таблица с поиском по номеру/названию, типом, оборудованием, расчётным/принятым временем, машинным временем, подготовкой, повторами и источником. Изменения локального справочника не меняют Google-источник и нормы проекта.
- План/факт по умолчанию группируется по сотруднику, проекту, полуфабрикату и интервалу календаря (день в неделе/месяце, час в масштабе «День»). Две кнопки представлений; щелчок по группе раскрывает все исходные задания с пагинацией. Убран постоянный дублирующий список первых 100 заданий; сводка факта свёрнута.
- Выпуск учитывается в момент завершения последней операции; промежуточная обработка и каждый день длинного задания не умножают количество. Бригадный выпуск общий для участников. В поштучном виде объём промежуточной операции подписан «обраб.», незавершённая работа — «В работе».
- Пояснения доступны в хинтах по наведению/фокусу. В материалах начальные остатки общие для плана/факта; корректировки включаются в «Приход»; плановые отгрузки пока не задаются. Нажатие дня раскрывает события.
- С1–С3 сохранены в docs/references/, их смысл и правила продолжения — в AGENTS.md. Маршрут пользователя не заменяет seed или сохранённый проект. Ключ и структура localStorage не изменены.

## Последнее изменение — общий баланс материалов и режим «Вытягивающий»

Реализовано 23.09.2026:

- Диапазоны K16:P32 и R16:U32 пользователь указал как смысловой референс roll-forward. Чтение Google Sheets в этой сессии завершалось тайм-аутом, поэтому формулы не считаются подтверждёнными. В коде расчёт остатков остаётся событийным и не зависит от формул Google Sheets.
- Во вкладке «Движение материалов» добавлен общий вид по всем полуфабрикатам с парами «План / Факт». По умолчанию показывается остаток на конец дня, отдельная кнопка переключает на дневной выпуск, ещё одна поворачивает оси. Детальный вид сохраняет расход, приход, выпуск, брак, отгрузки и события по дням.
- Кнопка «Отгрузка» открывает форму только для Final. Отгрузка записывается как фактическое отрицательное движение, поэтому готовый склад уменьшается, а отрицательный остаток блокируется доменной проверкой.
- В автопланировании добавлен `pull` / «Вытягивающий». Он использует общий планировщик, но при выборе в один момент времени отдаёт приоритет upstream и допускает downstream только при готовом материале и свободной возможности продолжить предыдущий этап.

Проверено: 46 тестов (32 доменных, 8 reporting, 6 для материалов и pull), TypeScript, production-сборка Next.js через `node node_modules/next/dist/bin/next build` и сборка автономного демо. Во встроенном Chromium через localhost проверены общий баланс с разделением План/Факт, переключатель дневного выпуска, поворот осей, детальный журнал и форма Final-отгрузки; расчёт режима «Вытягивающий» вернул один сценарий. Тестовые изменения нормы и проекта не применялись.

База/API/worker не менялись; интеграцию с PostgreSQL повторно не запускали. Прямая production-сборка `node node_modules/next/dist/bin/next build` прошла; составная команда `pnpm build` в этой сессии упёрлась в `EPERM` при попытке `prisma generate` переименовать занятую Windows DLL, после чего проверка продолжена без изменения схемы Prisma. Ограничения Docker, Safari/file://, резервного восстановления и живого OAuth ниже остаются в силе. Пользователь уже открывает локальный HTML: после завершённой сборки достаточно обновить ту же вкладку, не переносить файл и не очищать данные браузера.

## Реализовано

- Русский интерфейс: проекты, ресурсный календарь, схема, нормативы, план/факт, материалы, сотрудники/компетенции, оборудование, операции, шаблоны, архив/корзина и источники.
- Направленный граф без циклов, один Final, ветвления и сборка по нормам расхода. Последовательные операции блока; отдельная расчётная норма и ручная поправка.
- Погонные, статичные и переменные нормы, машинный предел, коэффициенты, независимые исполнители и обязательная бригада. Подготовка отдельно от передаточных частей.
- Смены, перерывы, допуски, количество машин, занятость других проектов, запас и поставки. Резервирование входов при запуске; выпуск доступен после завершения.
- Три режима: варианты первой отгрузки, самое раннее найденное завершение заказа и вытягивающий приоритет предыдущих этапов. Расчёт создаёт отдельный вариант, затем применяется с проверкой revision и снимка данных. Есть расшифровка свободных интервалов.
- Факт с частичным/нулевым выпуском, паузами и браком; дневной журнал движений с внутридневными событиями. Нельзя отгрузить отсутствующий запас.
- PostgreSQL, миграция, версии проектов, аудит, очередь worker; API `/api/v1`, авторизация одного планировщика, проверка Origin, шифрование OAuth-токенов.
- Импорт разрешённых Google-листов с предварительным просмотром и диагностикой, экспорт/импорт JSON schemaVersion 1, скрипты резервного копирования и восстановления.
- Автономное демо с localStorage и расчётом в Web Worker.

## Ограничения и ещё не подтверждено

- Docker отсутствовал: сборка образа и перенос Compose на целевом сервере не проверены.
- pg_dump/pg_restore отсутствовали: реальное восстановление резервной копии ещё не проверено.
- macOS/Safari не проверены. file:// заблокирован политикой встроенного браузера; тестировали тот же автономный файл через локальный HTTP preview.
- Живой Google OAuth-импорт требует Google Cloud client и подключения владельцем. Проверки парсера не подтверждают полный обмен с Google.
- Поиск эвристический: несколько размеров партий и два приоритета, без гарантии оптимума. Минимальная перебираемая партия `ceil(объём / 200)`.
- Если любое задание передаточной партии закреплено/начато/имеет факт, сохраняется вся цепочка этой партии. Структурные изменения маршрута с заданиями требуют копии проекта.
- Подготовка начисляется на запуск операции на наборе ресурсов; отдельный интерфейс управления несколькими производственными запусками не выделен.
- Нормы и маршруты хранятся в версионном JSONB проекта; это не отдельные реляционные таблицы каждой операции маршрута.
- Учёт запасов ведётся внутри проекта. В v1 нет глобального перепланирования, параллельных операций внутри блока, автоматической переработки брака и многопользовательских ролей.
