# Правила работы с проектом

Перед изменениями прочитайте `WORK_CONTEXT.md` и соответствующие разделы `README.md`.

## Сохранение рабочего контекста

- После завершённого изменения обновляйте `WORK_CONTEXT.md`: результат, затронутые части, реально выполненные проверки, известные ограничения и следующий конкретный шаг.
- Разделяйте «реализовано», «проверено» и «не проверено». Не объявляйте Docker, OAuth, Safari или восстановление БД проверенными на основании только сборки кода.
- Поддерживайте воспроизводимые команды проверки. Не сохраняйте временные PID, cookies, токены, пароли и содержимое пользовательских БД.
- Фиксируйте законченные проверенные изменения осмысленными коммитами. По запросу сохранения на GitHub отправляйте коммиты в подключённый `origin` и проверяйте совпадение локального и удалённого HEAD. Не переписывайте опубликованную историю.
- Для отдельной разработки используйте ветки `codex/<описание>`. Перед работой проверяйте текущую ветку и незакоммиченные изменения пользователя.

## Инварианты платформы

- Расчётный модуль `src/domain` не зависит от Next.js, Prisma и Google API.
- Google Sheets читаются только через серверный OAuth `spreadsheets.readonly` и явный список разрешённых листов. Исходные таблицы не изменять.
- Факт, движения, исходный утверждённый план, закреплённые задания и чужие проекты не заменять автопланированием.
- Проектные нормы версионируются отдельно от справочников. Звёзды сотрудника не меняют скорость; её задаёт коэффициент.
- Не скрывать неизвестные нормы и ошибки источника нулями. Демонстрационные данные должны быть отличимы от подтверждённых.
- Расписание — лучший найденный допустимый вариант, без обещания глобального оптимума.
- Типовой шаблон внутри платформы копирует маршрут, нормы и параметры, но не факт и бронирования.

## Проверки

Для изменений расчёта, API и хранения: `pnpm test`, `pnpm typecheck`, `pnpm build`. Для изменений UI или общего расчётного модуля обновляйте `pnpm demo` и проверяйте подходящий пользовательский сценарий.

`scripts/integration.mjs` изменяет только специально подготовленную локальную тестовую БД. Не запускайте его на рабочей базе. Порядок запуска описан в README. После успешной проверки не повторяйте её без новых изменений или причины.

Не коммитить `.env`, Google-токены, тестовую базу/секреты из `test-results`, `node_modules`, `.next`, резервные копии и ZIP-сборки. Готовое автономное демо `demo/production-planner.html` входит в репозиторий.
