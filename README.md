# Поток — планирование производства

Веб-платформа для маршрутов сборки, нормативов, ресурсного плана, факта и движения полуфабрикатов.

Репозиторий: [SaveOurSouls/PRODUCTION_PLANNER](https://github.com/SaveOurSouls/PRODUCTION_PLANNER). Текущее состояние, подтверждённые проверки и оставшиеся шаги — в [WORK_CONTEXT.md](WORK_CONTEXT.md), правила продолжения разработки — в [AGENTS.md](AGENTS.md).

## Быстрый просмотр

Готовый `demo/production-planner.html` можно открыть двойным щелчком в Chrome, Edge или Safari на Windows/Mac. Установка и доступ к сети не нужны. Ниже команды только для пересборки демо из исходников:

```powershell
pnpm install
pnpm demo
start demo\production-planner.html
```

Демо автономное: данные сохраняются в localStorage этого браузера. Оно не подключается к Google Sheets и не требует PostgreSQL.

## Рабочий запуск

1. Скопируйте `.env.example` в `.env` и задайте секреты. `SESSION_SECRET` должен быть не короче 32 символов, `TOKEN_ENCRYPTION_KEY` — 64 hex-символа.
2. Запустите `docker compose up -d --build`.
3. Откройте `http://localhost:3000` и войдите логином из `PLANNER_LOGIN` и паролем из `PLANNER_PASSWORD`.
4. Для Google Sheets создайте OAuth Web Application. Redirect URI: `${APP_URL}/api/v1/google/callback`. Доступ запрашивается только как `spreadsheets.readonly`.

Без Docker для интерфейса: `pnpm dev`. Для расчётов с PostgreSQL нужен отдельный `pnpm worker`.

Для локального запуска нужны Node.js 22.12+ и pnpm 11.19.0. После `pnpm install` выполните `pnpm db:generate` и `pnpm db:migrate`. CLI Prisma и Next.js читают `.env`; для отдельного worker используйте `node --env-file=.env node_modules/tsx/dist/cli.mjs src/server/worker.ts`. В Docker переменные передаются автоматически. Рабочая база создаётся пустой; кнопка «Загрузить пример» добавляет обезличенный демонстрационный проект.

Пароль PostgreSQL в Compose входит в URL: удобно использовать случайный hex-пароль. Пример генерации секрета: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Задайте разные значения для пароля БД, пароля планировщика, SESSION_SECRET и TOKEN_ENCRYPTION_KEY. При переносе сохраняйте TOKEN_ENCRYPTION_KEY вместе с БД: он нужен для расшифровки Google-токена. Для внешнего сервера установите HTTPS reverse proxy и соответствующий APP_URL.

## Источники

Импорт по умолчанию читает только `ЗАГРУЗ`, `Нормы`, `Лист14`, `БД. СОТ` из первой таблицы и `БД.ОП` из второй. Каждый импорт создаёт снимок и показывает диагностику до применения. Проектные нормы версионируются и не перезаписываются обновлением справочника.

- У второй таблицы проверяется gid `895010191` для `БД.ОП`.
- Google Sheets API должен быть включён в Google Cloud. Пользователь подключает свой аккаунт на странице «Источники данных»; OAuth-токен хранится на сервере в зашифрованном виде. Запись в Google Sheets отсутствует.
- Колонки сопоставляются по заголовкам; в текущем источнике номер проекта — E, комментарий — A, календарь — Q. Первую строку блока сотрудников можно настроить (по умолчанию 55). Из `ЗАГРУЗ` импортируются карточки проектов; существующие календарные ячейки сохраняются в снимке как референс, поскольку они не определяют однозначно операцию, количество и партию.
- Единицы времени без подписи необходимо подтвердить в настройках импорта. Пропущенные числовые компоненты и ошибки формул блокируют применение. Отсутствующая подготовка отмечается отдельным предупреждением с принятым значением 0.
- `Нормы` и `Лист14` сохраняются как снимки и проверяются на противоречия. Автоматически превращать неоднозначные табличные нормы в утверждённые проектные нормы нельзя.
- Допуски, звёзды и коэффициенты задаются в карточках сотрудников. Звёзды не умножают скорость.

Демонстрационный маршрут: разделение плат → пайка → отмывка/ОТК → упаковка. Референсные производительности 125, 50 и 545 шт./ч переведены в секунды на единицу. Объём 7000 шт., упаковка, оборудование, состав команды, допуски и календарь — демонстрационные значения; это не утверждённый производственный план.

## Расчёт и хранение

`src/domain` — самостоятельный TypeScript-модуль без Next.js, Prisma и Google API. В нём находятся нормы, граф, смены, резервирование, факт, материальный баланс и эвристический поиск расписаний. `src/server/worker.ts` забирает задания из PostgreSQL через `FOR UPDATE SKIP LOCKED`. Статусы: queued, running, done, error. UI показывает до пяти компромиссных вариантов первой отгрузки либо один вариант самого раннего завершения заказа.

Перебираются размеры партий и два приоритета распределения. Результат — лучший найденный вариант, без гарантии глобального оптимума. Минимальная перебираемая партия равна `ceil(объём заказа / 200)`; настройки переходов могут увеличивать её. Подготовка начисляется на производственный запуск операции на наборе ресурсов; передаточные части этого запуска её не повторяют. Независимые исполнители используют разные места оборудования, обязательная бригада занимает всех участников и рассчитывается по наименьшему коэффициенту.

При пересчёте сохраняется целиком передаточная партия, если любое её задание закреплено, началось или имеет факт. Это сохраняет цепочку операций такой партии. Применение проверяет версию и снимок данных; устаревший расчёт отклоняется. Первый применённый план хранится в baseline, все версии — в ProjectVersion. Факт и журнал запасов не заменяются расчётом.

PostgreSQL хранит проекты, задания, факт, движения, версии, справочники, очередь, снимки импорта, аудит и зашифрованные credentials. Доменные объекты сохраняются в JSONB, связи проекта с заданиями/фактом/движениями — отдельными таблицами. Все изменения проходят сериализованную транзакцию. Импорт и экспорт проекта имеют `schemaVersion: 1`.

## API v1

Все маршруты находятся под `/api/v1`. Запись требует сессию планировщика и заголовок `Origin`, совпадающий с APP_URL.

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | auth/login, auth/logout | Вход и выход |
| GET | workspace | Согласованный снимок рабочей области |
| POST | projects | Создать или сохранить проект с проверкой revision |
| POST | projects/:id/clone | Создать проект или шаблон без факта/бронирований |
| POST | projects/:id/close, reopen, delete, restore | Жизненный цикл; delete требует `{confirm: "номер проекта"}` |
| GET / POST | projects/:id/export / projects/import | Перенос JSON |
| POST | projects/:id/assignments, actuals, movements | Назначение, факт, движение |
| POST | projects/:id/plan | `{mode: "first"}` или `{mode: "throughput"}`; ответ 202 и job id |
| GET | jobs/:id | Статус и рассчитанные варианты |
| POST | jobs/:id/apply | Применить `{scenarioId}` |
| POST | catalog/employees, machines, operations | Справочники и календари |
| POST | google/connect | URL подключения OAuth |
| GET | google/callback, google/status | Подключение и состояние |
| POST | imports/preview, imports/:id/apply | Снимок/диагностика и отдельное применение |

## Резервное копирование и перенос

```powershell
node scripts/backup.mjs backups/planner.dump
```

Скопируйте исходники, `.env` и dump на новый сервер. Выполните `docker compose up -d --build`, затем:

```powershell
node scripts/restore.mjs backups/planner.dump --replace-database
```

Восстановление останавливает app и worker, заменяет данные planner через `pg_restore --clean` и запускает процессы снова только после успешного восстановления. Бинарный dump передаётся напрямую через поток, без текстового перенаправления PowerShell. Проверяйте восстановление в отдельной тестовой БД до замены рабочей. Том `planner-db` сохраняется при обычном `docker compose down`.

## Проверки

```powershell
pnpm test
pnpm typecheck
pnpm demo
```

Расчётные тесты проверяют формулы погонных/статичных/переменных операций, 6,5-часовой календарь, сборку с расходом компонентов, буферы, пересечения ресурсов, факт, импорт и сохранение закреплённых заданий.

Дополнительная локальная интеграция (только отдельная тестовая БД):

```powershell
node scripts/test-postgres.mjs
# В другом терминале:
node scripts/with-test-env.mjs node_modules/prisma/build/index.js migrate deploy
node scripts/with-test-env.mjs node_modules/tsx/dist/cli.mjs scripts/seed.ts
node scripts/with-test-env.mjs node_modules/next/dist/bin/next start --hostname 127.0.0.1
# В третьем терминале:
node scripts/with-test-env.mjs node_modules/tsx/dist/cli.mjs src/server/worker.ts
# После запуска:
node scripts/integration.mjs
```

`embedded-postgres` — только инструмент локальной проверки; в Compose используется официальный PostgreSQL 16. Временные данные и секреты находятся в игнорируемой `test-results/`. Интеграционный тест создаёт свои проекты и проверяет вход, очередь, применение, устаревший снимок, факт/брак, перенос JSON, шаблон, корзину и защиту Origin.

Статус проверки на 23.09.2026: 30 тестов, TypeScript, production-сборка, миграция и сквозной сценарий с локальной PostgreSQL прошли. Демо проверено во встроенном Chromium на Windows через локальный preview-сервер. Прямая проверка file:// заблокирована политикой встроенного браузера; файл содержит встроенные JS, CSS и worker без внешних зависимостей. На этой машине нет Docker, pg_dump/pg_restore и macOS: сборка контейнеров, реальное восстановление dump и Safari требуют проверки на целевом окружении. Живой OAuth-импорт требует настройки Google Cloud и подключения аккаунта владельцем.
